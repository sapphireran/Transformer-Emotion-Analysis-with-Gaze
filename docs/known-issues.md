# Known issues in the original personal scripts

These are notes for future-me (and anyone reading this checkout). The example package works around them; it does not silently rewrite the trainers.

## `model_full_SST.py` test metrics use the last batch

In the test loop, predictions are assigned rather than accumulated:

```python
preds = torch.argmax(logits, dim=1)
all_preds = preds.cpu().numpy()
all_labels = labels.cpu().numpy()
```

With `batch_size = 256` and 1186 test rows, that is four full batches plus a remainder. The printed `Test Acc/P/R/F1` line is the remainder only.

Validation is fine (`extend` is used there). If you re-run Track B, change those two lines to `extend` before trusting a test number.

## Checkpoint message says F1, tracks accuracy

```python
if val_acc > best_val_acc:
    ...
    print(f"... with F1: {best_val_acc:.4f}")
```

The file name is still a good breadcrumb (`best_roberta_eye_tracking_model.pth`). The printed “F1” is accuracy.

## `models/` is not created

`torch.save(..., 'models/best_{model_type}_model.pth')` fails if `models/` does not exist. Create it before Track B. The directory is gitignored.

## Windows path in `get_matfiles`

```python
subdir='\\ZuCo_mat_data\\'
path = os.getcwd() + subdir + task
```

On this Linux checkout that becomes `/workspace\\ZuCo_mat_data\\task1`. The MATLAB sources are not committed, so the examples never call this. Re-extracting ZuCo needs `pathlib` or `os.path.join`.

## Subject 3 is a different length

`ZuCo_et_csv_data/3_SR.csv` has 299 data rows; the other eleven files have 400. `DataTransformer` documents the skipped range for `task1` / subject 2 in MATLAB indexing (subject index 2 → file `3_SR.csv`). Row-wise `groupby(level=0).mean()` in `get_average_sentence_level.py` still emits 400 averaged rows because the other readers fill those ids. Treat reader-3 values as missing on the tail, not as zeros, if you recompute agreement.

## Two scripts build `ssts_ZuCo.csv`

`convert_full_SST.py` writes `ZuCo_SST_data/ssts_ZuCo.csv` from `ZuCo_SST_data/all/{LABEL}/*.txt`.
`ZuCo_SST_data/save_SST_data.py` writes `output.csv` from `all/{LABEL}/*.txt`.
The `all/` folder is not in git. The committed `ssts_ZuCo.csv` is the source of truth for labels.

## `spilt.py` is not a typo you have to keep

Both dataset folders use that filename. They are hold-out cutters. Track A ignores them.

## Hard-coded Hub downloads

The trainers call `from_pretrained('bert-base-uncased')` / `roberta-base` at import-of-model time. Offline machines need a prior cache. The sklearn examples never touch the Hub.

## `convert_sst_to_et.py` downloads NLTK `punkt`

First run wants network. The checked-in full SST tables already exist, so the examples skip this script.

## Unused imports in `utils_ZuCo.py`

`gzip`, `math`, `scipy` (the package) are imported and unused. Harmless.

## Scatter plots in `result/`

`train_data_scatter_hist_plots.png` and friends are from an older predicted-gaze dump (axes like `nFix`, `FFD`). They are not regenerated by `examples/02_gaze_feature_report.py`, which writes `examples/output/gaze_feature_report.png` instead.
